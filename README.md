# Мастерская · 0.6.0

Локальное приложение для учёта 3D-печати и покраски. React + TypeScript + Vite; данные, фотографии и история хранятся в IndexedDB текущего браузера. Сервер и регистрация не нужны.

## Обновление существующей мастерской

**Сначала скачайте ZIP базы в настройках старой версии.** Затем замените файлы приложения и откройте его на прежнем адресе в том же браузере. Миграция данных выполняется автоматически и сохраняет склад, резервы, историю и снимки производств. Подробности: [docs/UPDATE-0.6.md](docs/UPDATE-0.6.md).

Архив исходников приложения и ZIP базы — разные файлы. В этой поставке нет вашей личной базы.

## Запуск

Нужен Node.js 22.12+.

```bash
npm ci
npm run dev
```

Выполняйте команды в папке `workshop`, рядом с `package.json`. Откройте адрес из терминала. Для проверки на пустой базе есть кнопка «Загрузить пример»: три изделия HEADLINERS с демонстрационными ценами и расходами. Реальная база не заполняется примером автоматически.

```bash
npm test
npm run build
npm run preview
```

Готовая сборка находится в `dist`. Не открывайте `index.html` двойным щелчком — нужен HTTP-сервер. Данные привязаны к адресу сайта, включая порт: при смене адреса перенесите базу через ZIP.

## Основной сценарий

1. В «Принтерах» добавьте оборудование. Средняя мощность и время — ручные оценки, подключения к принтеру нет.
2. В «Материалах» выберите товар из каталога или заполните свою позицию. Укажите объём упаковки, цену, остаток и «Порог пополнения». Каталог не сообщает, сколько у вас материала.
3. Создайте проект и рецепт. Расход может быть на экземпляр или на всю партию. Поддержки, brim и продувку включайте в расход из слайсера. Компоненты смеси не дублируйте отдельными строками без необходимости.
4. На странице проекта откройте доску и расположите референсы. Доска общая для изделия, а пожелания конкретного заказчика записывайте в его производство.
5. При запуске выберите количество, принтер и один общий либо отдельные запуски. Время партии относится ко всей партии. При необходимости заполните заказчика.
6. Запуск резервирует материал. Смена этапа, отметка задачи и заметки не списывают его. Списание происходит при завершении, отмене или браке с подтверждённым фактическим расходом.
7. В «Инвентаризации» сверяйте физические остатки. Регулярно скачивайте ZIP в «Настройках» или через кнопку в боковом меню.

Пример: 300 г на складе, резерв 200 г → доступно 100 г. Завершение с расходом 200 г оставляет склад 100 г и резерв 0. Повторного списания нет. Отмена без расхода освобождает резерв.

## Доска проекта

Добавляйте карточки кнопками; текстовые виды можно перетащить с панели, изображения — перетащить с компьютера. За заголовок карточка перемещается, за края выделенной карточки меняется размер. Карандаш или двойной клик открывает редактор. Shift позволяет выделить несколько карточек и собрать их в группу. На пустом месте перетаскивается полотно, колесо меняет масштаб; Fit View показывает все карточки.

Ctrl/Cmd+Z отменяет действие, Ctrl/Cmd+Shift+Z повторяет, Ctrl/Cmd+D дублирует выделение. История действий действует до закрытия доски; расположение и содержимое сохраняются постоянно. Перед закрытием вкладки дождитесь «Сохранено».

Удаление карточки изображения оставляет файл в «Файлах проекта». Используемый на доске или как обложка файл защищён от удаления. «Своя смесь» на доске — визуальная заметка с цветом, не расчётная смесь рецепта.

## GitHub Pages

В комплекте `.github/workflows/pages.yml`. Разместите содержимое `workshop` в корне репозитория, включая `.github`. В Settings → Pages выберите GitHub Actions. Push в `main` запускает установку, тесты, сборку и публикацию `dist`. Публикация в ваш репозиторий в рамках этой поставки не выполнялась.

Маршруты используют `#/...`, ассеты относительные (`base: './'`). Разные репозитории на одном домене Pages разделяют origin и поэтому одну БД `masterskaya-v1`. Для независимых установок измените имя БД до первого использования; существующие данные сначала экспортируйте.
