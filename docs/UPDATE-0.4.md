# Обновление до 0.4

## Перед обновлением

1. Откройте старое приложение на привычном адресе.
2. Скачайте ZIP базы из настроек и сохраните отдельную копию. Это резервная копия ваших данных, а не архив исходников.
3. Закройте другие вкладки мастерской, остановите старый dev-сервер, если он запущен.
4. Распакуйте новую версию отдельно. Выполните `npm ci`; для публикации — `npm run build`. Переносить `node_modules` старой версии не нужно.
5. Запустите приложение на прежнем origin: тот же протокол, домен и порт. При работе через GitHub Pages используйте прежний адрес.

## Что произойдёт с базой

Имя IndexedDB сохраняется: `masterskaya-v1`. Версия структуры Dexie повышается с 1 до 2. В одной транзакции создаётся индекс метаданных изображений, добавляются новые коллекции и доски. Старые текстовые заметки проекта переносятся в ленту, старые фото — в группы доски с прежними ID файлов. Повторное открытие не дублирует карточки.

Складской журнал, активные резервы, рецепты и исторические снимки запусков не пересчитываются. Сам каталог также не изменяет склад. Внешний вид и локальные настройки уведомлений сохраняются в пределах того же браузера.

После обновления проверьте несколько материалов, активное производство, старые фотографии и скачайте уже новый ZIP.

## Перенос на другой адрес или компьютер

В новом приложении откройте «Настройки» → восстановление ZIP и выберите старую резервную копию. Перед подтверждением приложение показывает состав данных. Восстановление **заменяет** текущую базу, а не объединяет её. Сначала экспортируйте текущую базу, если она нужна.

Поддерживаются старый ZIP формата 1 со схемой данных 1 и новый ZIP формата 2 со схемой 2. Неизвестные версии, отсутствующие изображения и некорректные ссылки отклоняются до замены данных.

## Если открыты две вкладки

Обычные складские команды выполняются в транзакциях. У каждой доски есть своя ревизия: изменение склада не мешает сохранению доски, но конкурирующие изменения одной доски требуют разрешить конфликт. При ошибке можно скачать JSON-черновик, затем загрузить актуальную доску из базы. Черновик — аварийный файл для ручного восстановления; отдельного интерфейса его импорта пока нет. Он не заменяет ZIP с изображениями.

После восстановления ZIP ревизии досок повышаются, чтобы старая вкладка не могла затереть восстановленную версию.

## Откат

Старая версия приложения не понимает Dexie v2 и новый ZIP. Для отката откройте старую сборку в отдельном браузерном профиле или на отдельном origin и восстановите **ZIP, сделанный до обновления**. Не удаляйте текущую базу ради отката и не импортируйте новый ZIP в старое приложение. Правки, сделанные после обновления, сначала сохраните новым ZIP отдельно.
