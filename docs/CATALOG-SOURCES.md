# Каталог: источники и обновление

Версия набора `2026.10.28`. В браузере нет запросов к внешним каталогам: `src/catalog/builtin.json` входит в сборку. Личные товары находятся в IndexedDB и не перезаписываются обновлением встроенного файла.

## Происхождение

- [Miniature Paints](https://github.com/Arcturus5404/miniature-paints), commit `22791a682e1d155da388f4f856cd7196cd9f2677`, MIT, copyright Rick Fleuren (2022). Используются названия/линейки/артикулы и ориентировочные HEX. Уведомление — `licenses/miniature-paints-MIT.txt`.
- [SpoolmanDB](https://github.com/Donkie/SpoolmanDB), commit `9d53d28703ba1bcc97ab504e069d437ae2053c5a`, MIT, copyright Donkie (2024). Используются характеристики филаментов и упаковки, когда они присутствуют. Уведомление — `licenses/SpoolmanDB-MIT.txt`.
- [ELEGOO Standard V2.0](https://www.elegoo.com/collections/resin/products/elegoo-standard-resin-v-2-0): небольшая вручную составленная выборка фактов, длина волны 405 нм и упаковки 1/2 кг. Описания и медиа не скопированы. HEX и плотность не придуманы.
- [Vallejo, каталог 2026](https://acrylicosvallejo.com/wp-content/uploads/2025/10/Catalogo_2026-R02.pdf): артикулы грунтов и лаков, названия финишей и подтверждённая упаковка лаков 60 мл. Сам PDF не включён. Неподтверждённые HEX и упаковки грунтов оставлены пустыми.

Точные URL каждого исходного файла, commit, дата получения и SHA-256 записаны в `catalog-sources/manifest.json`. Снимки лицензированных исходников включены в `catalog-sources`; ссылки на графические образцы внутри исходных Markdown не загружаются приложением. Сторонние графические файлы в пакет не включены.

HEX — экранный ориентир. Он не гарантирует совпадение реальной краски и не позволяет вычислить физический рецепт смешивания. Температуры и плотности — справочные сведения из источника, не автоматические настройки принтера.

## Воспроизводимая сборка

Нужен Python 3; сторонние пакеты не требуются.

```bash
python3 scripts/import-catalog.py catalog-candidate.json
```

Импорт не обращается к сети. Он проверяет SHA-256 исходников, преобразует выбранные записи, добавляет ручную выборку и применяет `catalog-sources/overrides.json`. Прямую запись поверх `builtin.json` скрипт запрещает, чтобы правки сначала прошли просмотр.

Для обновления: измените закреплённые ревизии в `scripts/fetch-catalog-sources.py`, осознанно скачайте новые исходники этим скриптом, сравните изменения manifest и данных, проверьте лицензии, затем получите candidate. Если расширяете число записей, поправьте лимиты импорта и тест количества. Не объединяйте товары только по похожему названию: SKU, линейка, материал и вариант могут различаться.

После проверки diff замените `src/catalog/builtin.json`, запустите `npm test` и `npm run build`. Сохраняйте стабильные ID существующих товаров. Ручные поправки вносите через overrides по ID, чтобы повторный импорт не стирал их. Пользователю для добавления личного товара скрипты не нужны — есть визуальная форма «Создать свой материал».
