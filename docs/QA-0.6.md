# Мастерская 0.6 — аудит и проверка

Дата: 3 ноября 2026 года. Поставка — исходники и сборка существующего приложения. Личная база пользователя не изменялась; проверки выполнялись на изолированной демонстрационной базе и синтетических изображениях.

## Подтверждённые причины и исправления

| Наблюдение | Что найдено в коде / при проверке | Изменение |
| --- | --- | --- |
| При 0% кажется, что остаётся краска | В старом интерфейсе активная маска автоматически рисовалась голубым поверх результата с собственной альфой 0.35, независимо от непрозрачности слоя. Это подтверждённый источник визуальной путаницы. | Временное выделение отделено от слоя. Подсветка не участвует в композиции; у неё отдельные настройки. Нулевой вклад слоя явно исключается. |
| Телесный/рыжий отличается от выбранного HEX | Старый новый слой по умолчанию использовал Canvas-режим `color`, сохраняющий светлоту исходника. Это закономерно меняет итоговый RGB; подсветка дополнительно меняла видимый оттенок. | Новый слой по умолчанию «Обычный», у всех режимов пояснения. HEX валидируется/нормализуется, отсутствующий цвет не подменяется. Точный RGB проверяется на непрозрачном контрольном пикселе. |
| Палочка сразу портит область окраски | Старое выделение записывалось прямо в маску активного слоя. | Отдельная временная маска; явные создание слоя, применение и отмена редактирования области. |
| Быстрые изменения могут дать устаревшую маску | У прежнего worker был один callback без проверки актуальности ответа. | Идентификаторы запросов; устаревшие ответы игнорируются. Изменение допуска пересчитывает тот же клик от исходной маски операции. |
| Слабая кисть зависит от частоты мыши | Для новой кисти введено явное правило покрытия одного мазка. | Максимальное покрытие вдоль всей траектории; сила применяется один раз к маске до мазка. Следующий отдельный мазок может накапливать покрытие. |
| История быстро заполняется параметрами | Изменения объединены в логические транзакции. | Один мазок/перетаскивание ползунка — один шаг; Undo/Redo хранит маски, слои и состояние редактирования. |
| Зум смещает точку под курсором | Дополнительный browser-тест выявил зависимость коррекции scroll от момента React-отрисовки и автоматического scroll anchoring. | Коррекция перенесена в layout effect после изменения размеров; scroll anchoring отключён у рабочей области. |
| Галочка покупки может восприниматься как приход | Новый список не смешивает эти действия. | Отметка хранит купленный объём. Приход — отдельная атомарная транзакция с ID складского движения и защитой от повтора. |

Оригинал не перерисовывается поверх самого себя: композиция каждый раз строится от неизменяемой основы и масок. Canvas устанавливает и восстанавливает параметры прохода. Исходная альфа применяется один раз к итоговой композиции.

**Не объявляем воспроизведённым:** точную последовательность ошибки на рабочем фото пользователя. Само фото ещё не предоставлено. Установлены причины в прежнем интерфейсе и проверены инварианты на контрольных изображениях; окончательная визуальная приёмка реального сценария остаётся открытой.

## Автоматические проверки

`npm test`: **133 теста, 7 файлов, все пройдены**. Из них 97 прежних проверок и 36 новых проверок перекраски/закупок.

Новые проверки покрывают:

- Lab-палочку: смежность, 4/8 соседей, весь кадр, фиксированный цвет образца, прозрачность и выход за границы;
- алгебру мягких масок, расширение/сжатие, растушёвку без изменения исходной маски;
- непрерывный мазок, независимость силы от частоты событий, ограничение кисти выделением;
- преобразование экранных координат, нормализацию HEX;
- явное создание слоя, пустое выделение, отмену/применение области, объединение ползунка в один шаг, независимый дубликат и отмену незавершённого действия;
- формулу закупок, отрицательный свободный остаток, границу порога, полный/частичный резерв, дополнительную партию, расход на запуск, разные ID одинаковых названий;
- сохранение заметок, ручных количеств и упаковок; увеличение потребности после покупки; неизвестную цену;
- отсутствие движения при галочке, защиту от двойного прихода, включая конкурентные транзакции;
- перенос закупок и связей через ZIP, обратную совместимость и защиту CSV от формул.

`npm run build`: TypeScript и Vite проходят. Сохраняются неблокирующие предупреждения зависимости React Flow о директиве `use client` и Vite о размере основного chunk. Сборка содержит worker и отдельные chunks доски/закупок.

## Проверка в браузере

Среда: Linux x86_64, Node 24.22.1, Playwright, **Chromium 153.0.8010.0 headless**. Проверены DPR 1 и 2, viewport 1366×768, 1280×720 и 1920×1080, светлая и тёмная темы. Скриншоты использованы для внутренней визуальной проверки, в поставку не включены.

Контрольные изображения:

- фигура из контрастных областей, 600×720 px, два слоя;
- RGBA-образец с альфой 255/128/0 для точного сравнения пикселей;
- крупное изображение 2048×1536 px, четыре слоя, для измерения алгоритмов.

Полный сценарий `scripts/browser-qa.mjs` проверяет:

1. Открытие редактора с доски и выбор изображения.
2. Отсутствие окраски до явного создания слоя.
3. 0% → 100%, точное совпадение HEX с контрольным RGB.
4. Отмену изменения области и историю полигонального выделения.
5. Автосохранение, повторное открытие после перезагрузки, внутреннюю версию документа 2 и наличие масок в ZIP.
6. Во всех четырёх режимах: повторные циклы 100% → 0% возвращают исходные RGBA; исходник не меняется; альфа 128/0 сохраняется.
7. Повторный пересчёт допуска, отсутствие накопления и отклонение устаревшего результата.
8. Растушёвку 8 → 0 от прежней маски; пересечение кистью; применение и отмену новой области.
9. Зум около 50%, 100%, 200%, удержание точки под курсором и pan. В проверенных случаях ошибка привязки менее 1 рабочего пикселя.
10. Потерю фокуса во время мазка: незавершённая краска отменяется.
11. Принудительный отказ записи `QuotaExceededError`: видимая ошибка вместо ложного успеха; после восстановления хранилища повторная запись и открытие восстанавливают новый цвет.
12. Галочку «Куплено» без складского движения и один приход при подтверждении формы.

В браузерных прогонах не было необработанных ошибок приложения. Дополнительный итоговый прогон DPR 2 также прошёл: свободное лассо с замыканием контура и горячая клавиша с русской раскладкой. Последнее измерение: Lab 381 мс, палочка 77 мс, расширение 71 мс, первая композиция 111 мс. Ошибок приложения не обнаружено.

### Измерения

Два завершённых прогона в указанной виртуальной среде, 2048×1536 px, 4 слоя:

| Операция | DPR 1 | DPR 2 |
| --- | ---: | ---: |
| Подготовка Lab | 382 мс | 365 мс |
| Смежное выделение, допуск 12 | 69 мс | 63 мс |
| Расширение на 20 px | 92 мс | 75 мс |
| Первая композиция четырёх слоёв без кэша | 140 мс | 123 мс |

Это измерение отдельных функций, **не гарантия FPS**. В приложении подготовка Lab и расчёты выделения/края выполняются в worker; композиция Canvas остаётся в UI-потоке. Крупные маски и много слоёв могут работать медленнее на слабом устройстве.

### Готовая сборка dist

Отдельный `scripts/production-smoke.mjs` запущен через Vite Preview, без импорта исходных модулей. Пройдены: старт пустой мастерской, загрузка демонстрационных данных, открытие доски, загрузка нового PNG, создание слоя палочкой через собранный worker, скачивание PNG, сохранение и переход «Материалы → Что докупить». Ошибок JavaScript и ответов ресурсов HTTP 4xx/5xx не было.

## Повторить проверки

```bash
npm ci
npm test
npm run build
```

Браузерная проверка — отдельная необязательная зависимость разработчика:

```bash
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run test:browser
```

Скрипт сам запускает Vite на `127.0.0.1:5181`, создаёт изолированный профиль браузера и наполняет только его демонстрационными данными. Порт должен быть свободен. Переменные: `QA_DPR=2`, `QA_OUTPUT` — каталог внутренних снимков, `QA_CHROMIUM` — путь к браузеру, `QA_PLAYWRIGHT` — путь к модулю Playwright. Скрипт не предназначен для запуска против личной рабочей базы.

## Что ещё проверить вручную

- **PA-30:** реальное фото пользователя, границы конкретной детали, оттенок и качество после экспорта. Фото не предоставлено; это открытая приёмка, не скрытый пройденный тест.
- Safari/Firefox и реальные сенсорные устройства; в этом окружении не проверялись.
- Диалог сохранения PDF/системный принтер и доступ к буферу обмена на целевом устройстве. Текст/CSV и печатная форма реализованы, но взаимодействие с ОС зависит от браузера.
- Длительная сессия с большой личной фототекой и реальное переполнение квоты. Отказ записи смоделирован, исчерпание физической квоты не выполнялось.

Редактор не использует ИИ-сегментацию и не обещает выделить сложный объект одним кликом. Исходники и маски сохраняются; старые производные ресурсы пока не очищаются автоматически ради совместимости истории доски и независимых вариантов.
